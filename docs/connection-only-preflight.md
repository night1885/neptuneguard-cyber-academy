# Connection-only preflight — preparation, not execution approval

This separate diagnostic is intended to test a restricted certification connection without starting Discord, the restoration application, registration, courses, or retention execution. Adding it does not execute it, change package.json, publish messages, deploy, or alter any hosting setting. Existing saved settings remain operator-confirmed; no successful worker connection is claimed yet.

The approved target is pinned in the helper to the previously reviewed academy hostname/database and neptuneguard_certification_app login. The helper requires an explicit verify-full TLS setting, reuses the existing strict connection loader and bounded pool configuration, and opens only one diagnostic connection. It requires both current_user and session_user to match the restricted login, rather than accepting an administrative session switched into another role. It checks its own pg_stat_ssl row for server-reported TLS 1.2 or 1.3. Future protocol/target changes require deliberate review, not a silent relaxation.

The only queries are BEGIN READ ONLY, database/current/session identity, the connection's TLS metadata, and COMMIT/ROLLBACK. It does not select application-table rows, agreement contents, audit events, or learner records, and performs no DDL/DML/grants. Its own client/pool are closed, including failure paths; it never closes the worker's existing pool. Driver exceptions, passwords, URLs, and CA contents are not included in its result/errors. The CLI emits a fixed generic failure object rather than driver details.

The standalone CLI requires an explicit --check argument and reads only the invoking process's existing environment through the helper; it does not auto-load dotenv files. A later separately approved command would be node certification-connection-preflight.mjs --check. Do not run it merely because this document exists, paste credentials into chat, copy production secrets to a developer machine, or deploy the restoration to make the file available without separate approval. Establish a reviewed execution/delivery method in the intended worker environment first. The current connector tool inventory has not supplied a worker-shell execution operation.

A successful probe establishes that the diagnostic process connected using its supplied settings and strict client TLS configuration. It does not establish that the current instructor entry uses those settings, that another process shares its environment, or that the restored application passes schema/agreement/channel/authorization checks. It does not verify every runtime permission or certificate policy independently of the real driver's TLS behavior. Normal application acceptance remains separate.

Mocked tests cover target/TLS validation before allocation, session identity, server TLS, bounded pool settings, metadata-only queries, sanitized failures, rollback discard, cleanup, and unchanged package entry points. They do not establish real provider connectivity or real TLS acceptance. Existing unit globs discover the tests; no new passing result is claimed before CI runs. Execution, restart, release/merge, configuration changes, or deployment require separate approval.
