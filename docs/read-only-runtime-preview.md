# Owner-only read-only runtime preview

CERTIFICATION_READ_ONLY_PREVIEW=true is a new opt-in runtime mode, not yet set on Render by this patch. It requires explicit matching owner/server/admin-channel configuration, enabled certification, and disabled general submission, application-closure and course-mutation runtime features. Existing manifest/schema/Discord readiness checks still apply. Defaults and normal-mode pool behavior are preserved.

The integrated wrapper admits only the configured owner and a reviewed administrative read-view allowlist. Unknown routes, registration, invited/self-service learner flows, approval/access/lab mutations, section login and retention/review actions are rejected before the underlying router. Outgoing buttons that do not belong to the read allowlist are disabled; section menus are filtered and a read-only banner is added. Directory-search forms remain read-only. Detailed lab-view routes not on the allowlist remain unavailable rather than being assumed safe.

The native pool adds default_transaction_read_only=on for preview connections. The router/services receive a facade that refuses raw client checkout, rejects non-read/multi-statement query shapes and executes accepted trusted queries inside BEGIN READ ONLY/COMMIT, with rollback and discard handling. This is layered application protection, not a new database role or a general SQL sandbox. Do not pass arbitrary client SQL; PostgreSQL read-only is a high-level transaction property, not a promise that no temporary, logging, provider or filesystem writes occur. Existing role privileges are unchanged.

Tests exercise the real guard and VM-evaluated actual runtime/pool-factory bodies with fixtures. A separate case uses disposable localhost certification_test only and is added to the existing PostgreSQL 16/18 CI matrix; it checks native write denial, DML-CTE and function-write denial, unchanged fixture data and recovery after rollback. Local execution does NOT establish real PostgreSQL, SDK serialization, Discord delivery or production acceptance until those checks actually run.

This would be a controlled production preview if later deployed against the existing worker/database: the authorized owner could read existing registration/access records. It is not isolated staging. No production learner rows were queried by preparation. The patch neither changes Render configuration nor merges, deploys, publishes controls, migrates/grants roles or runs retention. Live preview enablement and the exact deployment revision require separate approval after CI/review. Full learner activation remains a separate release.
