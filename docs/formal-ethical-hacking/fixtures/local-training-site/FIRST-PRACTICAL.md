# First practical: who can read this note?

Supporting draft, not a new canonical course entry or learner activation. Use the existing LEARNER-VALIDATION.md setup/scope gate first. Missing supported guest/tooling, ordinary-user approval, material transfer, isolation review, support/recovery or private evidence handling means BLOCKED. This is a repaired fictional baseline, not a real login or intentionally vulnerable website.

## Mission
Explain an object-ownership decision using a prediction, a bounded observation and a testable conclusion. A good outcome is accurate reasoning, including an honest blocker; it is not finding a vulnerability at any cost.

## 1. Predict before browsing
Read the reviewed application source. Identify the fixed fictional actor, the two note owners and the ownership comparison. For each fixed path, write the predicted result in PRACTICAL-REPORT.md before making a request. Explain the difference between knowing an object's path and being allowed to read it. The fixed actor is a test assumption, not authentication.

## 2. Observe within the released manual brief
Follow LEARNER-VALIDATION.md exactly: at most four intentional GET navigations in a separately approved session, using only the launcher-printed owned loopback origin and /, /exercise/own, /exercise/other, /exercise/missing. No queries, guessed routes, extra tools or credentials. The 20-application-attempt allowance includes possible browser background requests. Do not reproduce CI's extra budget-rejection request or POST check manually.

Record rendered training/no-login labels, fictional own-note behavior and selected denied/missing results. Use approved browser tools only to inspect the already-generated requests. Distinguish the status, visible text and interpretation; a 404 by itself is not proof that no private content was returned. Stop on uncertain accounting or an unexpected result and use the approved support route.

## 3. Explain, do not invent a finding
On this reviewed baseline, an other-note denial is expected policy behavior. If your actual observations match predictions, report that the selected check behaved as expected; do not label normal denial a vulnerability. If there is a discrepancy, record minimal fictional evidence and uncertainty without exploring more paths. Equal selected denied/missing responses do not establish timing privacy, complete non-enumeration or real multiuser security.

## 4. Design the regression in words
Describe a hypothetical defect that omits the ownership comparison, the fictional record it might expose, and a test that should fail for that defect and pass after repair. Do not modify the served application or swap in a flawed starter. Independent repair work belongs to the separately scoped [ownership lesson](../../lessons/EH-WEB-04.md) and its own prerequisites/permissions; this guide does not authorize running it.

## 5. Close and report
Follow the worksheet's normal stop and separately approved restart steps. Record actual evidence or a blocker, then complete PRACTICAL-REPORT.md. Keep human observations, source predictions, CI conclusions and copied report fields separate. No grade, award, progression, public hosting, company-site testing or supported-hardware claim follows from completing this draft.
