# Disposable intake storage adapter — source-only batch

Base: dd8a355656cadd74dbb98712dc65202f5b1cbf25. Branch: feat/formal-intake-adapters.

## Implemented candidate
The reusable default-off adapter exposes the existing coordinator's SQL-backed binding, journal, receipt, submit, read, review and draft-claim/finish ports plus bounded receipt discovery. It accepts a supplied restricted worker pool and never creates a pool, SDK client or listener. Explicit disposable-CI environment checks and a real backend identity/schema/privilege probe precede use. These are guardrails, not authentication of arbitrary supplied objects or proof of production separation.

The add-on installs only after all four existing empty disposable fixtures. It creates three protected metadata tables and restricted functions, including atomic work-record/journal bootstrap. Journal transitions use record locking and operation IDs; a reconstructed coordinator reuses the stored available channel mapping. New work records use adapter_create_record, which atomically creates a one-use unprovisioned journal. A missing/erased journal fails closed rather than being mistaken for permission to provision another channel. A SQL advisory source lock plus record/authority locks serializes submission with due-draft inspection. Original source uniqueness is retained, body bounds are enforced on both sides, and original request UUIDs are mapped transactionally to the existing receipt key format. Discovery returns bounded authorized request/report/revision/deadline metadata, not evidence bodies. Reviewer authority is restricted to the configured fictional owner identity and current fixture record grant. Baseline worker functions that would bypass the adapter are revoked only within the new add-on test installation; original fixtures/tests stay unchanged.

## Approved design, no extra retention window
The owner approved P1-P4 on October 28, 2026 at 21:01 EDT: creation-anchored 24-hour unsubmitted drafts; per-source/revision isolation without channel/account cleanup; owner-only scoped pilot review without self-review; plain-text excerpts limited to 2,000 Unicode code points/8,192 UTF-8 bytes without attachments/forwards/arbitrary retrieval or truncation. The subsequent clarification approved no extra retention period.

No grace period or indefinite tombstone is introduced. Submitted request metadata uses the original report deadline and cascades with its report. The current journal association transfers to the latest submitted report deadline rather than preserving a history of old report references. An unsubmitted provisioning journal has a finite 24-hour technical bound; expired journals fail closed instead of blindly creating replacement channels. This bound is not proof that every unseen Discord draft was discovered or erased. Draft claims carry the ORIGINAL draft deadline, not claim-time-plus-a-new-window. Confirmed and unknown finish paths remove the claim; unknown deletion still raises failure, never success. Admin-only fixture cleanup removes expired adapter metadata; erasure cannot authorize recreation under the old record. It is a test primitive, not a live scheduler. Deleting metadata is not proof of external erasure; the existing fixture's deletion-pending state represents an overdue failure, not permission to extend retention.
