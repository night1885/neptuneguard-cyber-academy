## Borrowed-provider contract
The caller supplies an already configured coordinator exposing prepare/preview/submit/recoverSubmission and an already initialized storage adapter exposing resolve/authorize/discoverReceipts plus literal-true ready state. The caller must ensure coordinator, storage, scope, account authority and trusted epoch clock actually match the configured rehearsal environment. Matching shapes/strings are not authentication and cannot prove provider consistency or environment separation. Methods retain their original receiver context.

One handle dispatches nmi: only to the existing intake boundary and nmr: only to the existing recovery boundary. Unrelated fws:/fnv: routes are ignored. Both routes share the same synchronous parent readiness AND storage readiness and the same nonnegative monotonic clock guard. Recovery timeoutMs remains the existing recovery-boundary option; coordinator waits remain owned by the supplied coordinator. No new global concurrency or durable-state guarantee is introduced.

The assembly owns only its two boundary instances. The intake delegate receives a coordinator facade whose dispose does not dispose the borrowed coordinator. Idempotent assembly disposal marks shared readiness false first, clears both boundary sessions/timers, and ignores later calls. It does not initialize, dispose or close shared coordinator/storage/pools. The parent owner remains responsible for outstanding-work handling and safe shared-provider shutdown; this API does not implement a drain barrier, cancel issued remote work, recall delivered messages or guarantee secure erasure. Already-started external reply delivery can still race shutdown.
