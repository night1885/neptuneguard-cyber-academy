# Detached intake receipt recovery primitive

Source-only rehearsal extension based on main 8758b8b87e6f7eb69abb263bfacfde2b4906cda8. No SDK client, listener, live identity, database adapter, production schema or learner-facing recovery route is added.

recoverSubmission(ctx, requestId) uses current submission authorization, the available private-channel journal binding and the scoped receipt provider. It validates receipt identity, source guild/channel/message metadata, source creation time and the original 24-hour deadline, then rechecks binding, channel and authorization before releasing a minimal acknowledgment. It never invokes submit, reads source content, resets retention or creates recovery storage. No missing-receipt fallback submission is allowed. Disabled coordinators expose the same method without provider access. Existing submission, review and draft paths and the interaction boundary remain unchanged.

The provider is trusted to bind the original request ID to the correct authorized receipt. Recovery uses the stored digest; it does not independently verify original preview content. Its envelope must include sourceGuildId. Original unit-fixture receipts omit that field; they are not recovery-compatible without an explicit provider update. Do not remove validation to accommodate an incomplete fake. The SQL provenance fixture already supplies the field, but database-backed recovery has not been executed for this change.
