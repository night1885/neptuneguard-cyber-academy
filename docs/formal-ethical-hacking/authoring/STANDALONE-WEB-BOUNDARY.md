# Standalone web-course boundary — approved scope clarification

Decision confirmed by the programme owner on 2026-11-01. The web course must be a standalone course, separate from CPTS, OSCP and GPEN preparation. It has its own course card, in-place button navigation, syllabus, practicals, assessments, progress and completion decision. The existing private-Discord, card-based learner experience and the complete programme scope remain unchanged.

Learners must not need to enrol in or complete CPTS, OSCP or GPEN preparation to enrol in or complete this web course. Necessary Linux, networking, HTTP/TLS and programming skills remain real prerequisites, but the web course must provide its own reviewed foundation bridge or assess equivalent skills. Reusing lesson material does not reuse course enrolment, saved state, evidence access, reviewer authority, lab permission, awards or completion.

The web course is the programme's intended home for advanced web-source analysis and preparation toward OSWE. That association is a direction for curriculum design—not a validated vendor alignment, official partnership, exam eligibility decision, completion guarantee or exam-pass promise. The CPTS, OSCP and GPEN preparation routes keep their existing structures and required web/API content. No other competency domain, professional pathway, student-built-lab requirement or release standard is reduced.

Planning labels W00-W08 are provisional design aids only. They are not canonical lesson IDs, a registered runtime course key, published content, working access rules or release evidence. No course is ready for learners solely because this boundary is agreed.

No runtime registry, catalogue, database, application, workflow, learner record, permission, Discord message or deployment is changed by this amendment. Existing authorization, privacy, hardware, assessment and approval gates remain in force.
