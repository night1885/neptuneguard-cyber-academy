# Private owner shared-review interaction handler - unpublished

This default-disabled handler prepares open/confirm/cancel button interactions around the staged shared-enrollment sessions. It is NOT installed in a runtime/router, published in Discord, or connected to a database, clearance writer, scheduler or deletion executor. No closed-application/audit review UI is included.

The handler checks the configured owner ID and server on every recognized interaction, ignoring Administrator permission and role names. It must receive authentic Discord-client interaction objects; passing arbitrary objects from an unverified HTTP/client payload is not authentication. Scope is pinned to explicit server/database/schema configuration.

A public or unknown-privacy entry point receives a newly deferred ephemeral reply. Only source messages whose message flags positively report Ephemeral are updated in place. The handler refuses previously acknowledged interactions without reading state and sends an ephemeral fallback instead. Owner/server denial and malformed action IDs also use ephemeral replies. Response payloads suppress mentions, clear old controls/embeds, show only Discord user ID, completed-course count and snapshot hash, and never echo raw errors, enrollment objects or permanent student IDs.

Button action IDs bind to a server-side random session token. Confirmation uses the explicitly labeled reviewed/no-preservation-required action and relies on native session revalidation, preservation/dependency blockers, expiry and single-use consumption. A successful callback returns a frozen truthy result with handled=true and an unsaved owner_review_intent; unrelated interactions return null. Future routers must handle this return contract explicitly and must not treat the intent as a stored clearance. There is no callback that writes or issues a clearance.

Success text states that the intent has not been saved or issued as a clearance and no deletion was requested. Storage, revocation coordination, authenticated runtime composition, dashboard placement, publication and production acceptance remain separate gates. A transport failure after token consumption can lose the unsaved intent and requires a fresh review; there is no retry claiming persistence or deletion success.

Local tests compose the actual new handler, actual session module and existing snapshot helper with verified Git blobs 7555c5700a18878d65bca0b444d95b3333b028dc and 00e10eb9a56ad4e1d31c6f03495477eb217ffa8e. Discord transport and state readers are fixtures. These tests do not establish actual SDK serialization/delivery, live private-message behavior, SQL consistency or authenticated production operation. No Discord publication, production query, grant, migration, live deletion, merge or deployment is included.
