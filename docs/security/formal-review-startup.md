# Default-off formal-review startup attachment

createFormalReviewStartupAttachment returns undefined unless enabled is explicitly true. An enabled factory is single-owner and can be injected as attachReview into createRestoredCertificationApplication. This batch does not edit restoration.js, add an environment enablement flag, publish controls or activate collection.

The attachment waits for both Discord client readiness and isCertificationReady before acquiring resources. It constructs the actual Discord source in administrator-and-learner mode, the native restricted course authorizer, its privacy gate, and the actual review composition. Current Administrator, assignment/exercise and reviewer authority callbacks remain required. The fixed source and reviewer modes cannot be overridden by resource options. Resource verification, store initialization and restricted course-reader checks complete before the interaction listener attaches. Certification readiness loss immediately makes operation admission and review readiness false; it does not reconstruct resources or cache prior authority.

The trusted createResources factory must return dedicated store, metadataPool, courseOptions, verifyAdministrator, authorizeReviewer, authorizeExercise, verifyResources and closeResources ports; optional receiptPool and recoveryEnabled enable existing receipt recovery. courseOptions includes the dedicated readPool, expectedDatabase and expectedLogin. Provider and resource ownership must not overlap with certification/community pools. Resource acquisition failures must clean up any partially acquired resources before rejecting; a returned resource object must expose closeResources even when another port is invalid. Config and identity are supplied as a frozen scope to the resource factory. Secrets are not included in diagnostic events.

closeResources runs once only after composition/provider drains succeed. It must close the factory-owned dedicated pools, not shared application resources. Stop admission precedes drain; a failed drain leaves resource closure unconfirmed and causes detach rejection. Startup waits at most 10 seconds by default, including readiness polling; a configurable ceiling of 30 seconds is enforced. The deadline stops admission and requests cleanup, but cannot force arbitrary trusted resource factories or database drivers to settle. Existing source and database transport deadlines remain mandatory, and parent application shutdown supplies its own final deadline.

Tests construct actual source/course/gate/composition modules with scripted SQL, authority and transport ports, and inject the attachment into the actual restored application. They establish neither live Discord permissions/API acceptance nor production PostgreSQL provisioning, rollback, dedicated-pool configuration or durable consent. Live notices and consent, resource provisioning/reconciliation, practical authorization, native acceptance, erasure/preservation integration and reviewed deployment configuration remain release gates. No Copilot review or release approval is claimed.
