# Formal review core — source-only candidate

No runtime listener, schema, pool, production adapter, channel, practical permission, evidence collection, deployment or learner record is created by this package. The core is default-off and disabled construction does not access providers. Existing reading delivery and Community Learning are unchanged. This is not the completed learner/reviewer workflow.

The core accepts trusted server-side actor/guild context, an immutable work binding and explicit course, exercise and owner-review authorizers. The owner cannot review their own report. A role name, client owner field, reading assignment or button token alone grants no exercise/reviewer authority. Exercise allowlisting selects supported identifiers; it is not practical authorization.

Plain text is bounded to 2,000 Unicode code points and 8,192 UTF-8 bytes without truncation or malformed UTF-16. Authenticated exact-source acquisition must establish the bound guild/channel/learner, fresh channel privacy, no bot/forward/attachment and authoritative creation time. A server-bound preview digest is required. Draft-source admission expires after 24 elapsed hours from creation. Report access expires 24 elapsed hours after submission; review and retry do not extend that deadline. These are access/admission checks, not implemented deletion.

## Mandatory production adapter contract

transaction must acquire the work row lock, return an immutable binding snapshot, and commit report/review mutation, revision compare-and-swap, minimal audit/operation receipt atomically. Any callback failure must roll back all changes. Store identities and report revisions must be unique and immutable. Concurrent calls must serialize or conflict without overwrites. Work expiry must follow the applicable draft/report deadline and must not make older reports or receipts live again. Report, feedback, receipt, audit and source-copy retention requires a separately implemented scoped purge, with no extra grace period or indefinite tombstone. Never use enrollment answers as evidence storage.

Required transaction methods are lockWork, findOperation, readReport, readReview, insertSubmission, insertReview and saveOperation. readReview returns null or the exact submitted report's bounded feedback, decision, expected submission revision and original expiry. The adapter must enforce immutable source uniqueness and define durable operation-ID collision handling and recovery. Work creation, discovery, channel journaling, review-copy tracking, PostgreSQL schema/privileges, purge execution and backup/provider handling are not supplied here.

Course authorization must freshly match the authoritative permanent student ID and exact active course assignment; exercise and reviewer checks must use real scoped grants and current authority. The SDK adapter, not client parameters, authenticates actor and server. Readiness must synchronously be literal true. Epoch clock validation/regression detection is local to this core instance, not durable trusted time across restarts. Expected source digests must come from a server-bound preview session, not an untrusted replacement value.

Rechecks occur during the transaction and before returning a protected response. Discord permissions and database commit/delivery are not atomic. A post-commit authorization failure returns no success but may leave a committed operation; the adapter must recover using the original operation ID. Disposal blocks new admission and rechecks, but is not a drain barrier, cancellation of issued provider work or erasure guarantee. Parent runtime must bound provider timeouts/concurrency, drain borrowed resources and reconcile unknown outcomes. No arbitrary URL retrieval or fixture execution is implemented.

## Validation

Thirty local Node tests passed with zero failures/skips using the actual core/policy and a scripted, serialized, rollback-capable in-memory transaction provider. They exercise source/preview binding, text limits, authority denial, revision checks, duplicate/concurrent retries, rollback on receipt failure, read isolation, bounded feedback, expiry, revocation, self-review denial, clock regression and disposal. This is not PostgreSQL, real Discord, full-checkout CI, independent review or production acceptance. The test filename is included by the existing certification test glob; its actual committed-head CI result must be checked separately.
