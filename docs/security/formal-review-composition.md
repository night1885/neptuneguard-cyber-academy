# Default-off review composition candidate

This library constructs the actual core, intake, learner controls/browser/discovery, owner flow/controls/browser/discovery and runtime bridge. Store, course-authorization and Discord-source adapters are supplied by trusted server code; this is not a factory for database pools, credentials, migrations or production configuration. All adapters must be bound to the same reviewed guild, learner identity/course policy and deployment resources before use.

Disabled construction reads no dependency options. Enabled construction and initialize register no listener and publish no command, panel, private entry or channel. attach is explicit and remains an activation-sensitive operation for a future runtime owner; this source commit calls none of these against a real client. No startup import is added.

Initialization requires literal external readiness and a literal true verifyResources result, then initializes the store and course authorizer in order. Checks after each asynchronous boundary stop later admission if shutdown or external readiness intervenes. Shared operational readiness requires initialized composition, literal store/authorizer readiness and fresh external readiness; exceptions deny admission. Exercise and reviewer authorizers remain separately supplied mandatory providers, not derived from reading access.

verifyResources is a trusted integration obligation, not an implemented audit: it must establish matching deployment bindings, metadata-reader profile/deadlines, source/privacy prerequisites, consistent removal policy, approved notices/consent and any required provisioning readiness. Passing a stub that returns true establishes none of these in production. This composition does not validate supplied adapters' hidden guild/role configuration or grant practical authority.

Ownership of the supplied adapters transfers only on successful construction; they must not be shared with another lifecycle owner. The module owns newly constructed controllers and both distinct discovery instances. Their metadata pool and the Discord client remain borrowed: neither pool.end nor client.destroy/login is called. Constructor failure disposes only newly built passive controllers and leaves supplied adapters caller-owned.

Detach closes shared admission first, stops source/core/intake/owner flow and store/course adapters, and delegates listener removal and handler draining to the existing runtime bridge. Resource draining follows successful handler drains. Errors retain the bridge's unconfirmed-shutdown semantics; rejected detach is not permission to close borrowed pools. Drain can wait indefinitely for providers that never settle. This is neither cancellation of issued work nor rollback nor erasure.

The regression suite uses the actual composition/core/controllers/browsers/bridge with scripted storage, source, readiness and authority adapters. It covers default-off behavior, no automatic registration, ordered and concurrent initialization, preflight/profile failure, retry, empty discovery routing, readiness revocation, disposal/drain ordering, shutdown during initialization and ownership boundaries. The existing certification test glob includes it. These new tests are not claimed locally executed or passed at a future uninspected head. They do not establish a PostgreSQL/source-HTTP integrated journey or native Discord acceptance.

Work/channel provisioning, real source/privacy and exercise authority integration, durable consent/recovery, cleanup/dependency reconciliation, reviewed notices, independent security review and final release acceptance remain gates. No production listener, evidence collection, migration, grants, publication, merge or deployment is authorized or performed by this batch.
