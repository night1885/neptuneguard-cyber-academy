# Metadata-only private-channel verification candidate

verifyPrivateChannel is a default-off source-reader API for a future authorized provisioning/resource-check flow. It makes two matching bounded snapshots of bot identity, guild owner, guild roles and one channel, using only existing constructed GET metadata routes. It never requests a selected message, message history, report body or attachment. The strict existing privacy profile, streaming/redirect checks, monotonic deadline, four-operation and sixteen-request limits, disposal and drain behavior are reused. No positive result is cached.

The server-bound scope may name the learner or configured owner as actor for this metadata-only operation. It still rejects self/bot learner targets and malformed bindings. This is not authentication, enrollment/course/exercise authorization, proof of work-row existence or collection consent. A trusted caller must establish those independently before provisioning or evidence intake. A boolean true reflects matching point-in-time snapshots, not continuous privacy, a durable signed proof or atomicity with a later database/Discord write.

readSource and its learner-only evidence rule are unchanged; the configured owner cannot use the new method to retrieve learner evidence. All existing message shape, digest-binding, timestamp and content admission checks remain in their existing layers. No startup call, channel creation, permission mutation, work insertion, practical activation, publication, merge or deployment is added.

Local execution passed all 69 source-reader tests with zero failures/skips, including the original regressions and new no-message, privacy drift, noncached recheck, owner-boundary, timeout/concurrency, disposal and transport cases. HTTP responses and credentials are fictional; no live Discord request or production readiness is established. Exact committed-head CI and later composed provisioning/native acceptance remain required. This is only a provisioning prerequisite; provisioning, consent/recovery, erasure and release gates stay open.
