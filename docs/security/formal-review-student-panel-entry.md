# Opt-in saved-report entry from private Student home

This source candidate adds a display-only hook to the existing handleCertificationLearner home response, which is used by the shared router under the restoration router. It changes no existing enrollment authorization, permanent student ID, introductory navigation, public panel, command registration or startup configuration.

The home handler invokes an entry provider only after its existing fresh service.getCourseAuthorization result includes a permanent student ID, and only when config.formalReviewPrivateEntryEnabled is literal true and config.formalReviewPrivateEntry is an enabled server-supplied provider. Only the minimal existing studentId is passed, not enrollment answers or acknowledgment records. The hook accepts at most one exact self-targeted Saved formal reports button row. Provider failures, foreign targets and malformed/extra rows leave the original home navigation intact.

The createFormalReviewPanelEntry factory is independently default-off. Its pure learner renderer requires current readiness, the configured native interaction application/guild/bot, a normal guild-text channel, a human non-owner actor, an acknowledged response and either explicit ephemeral response state or a bot-authored ephemeral origin. Recorded origin user identity must match when present. Missing or inconsistent evidence yields no row. Trusted native interactions and server-owned providers are mandatory; this helper is not an authentication boundary for client JSON.

The button targets the existing frv:list:<actorId>:0 report browser. It displays no new student ID and grants no report, exercise, reviewer or practical access. Report discovery and reads must still use the real composition/core authorization and current assignment checks. This entry is for saved reports, not new work/channel provisioning or evidence submission.

No environment parser, application startup, listener attachment or public publication is changed. The new programmatic option and provider are not configured by existing startup code. A future reviewed runtime owner must supply a matching helper whose readiness follows the actual review composition, establish resource/privacy profiles and separately approve any activation. Owner/reviewer panel entry remains separate work.

Local results: 20 pure helper tests passed, zero failed; seven actual-handler/installed-SDK integration cases were skipped because the project SDK is unavailable locally. The modified learner handler passed syntax checking against baseline Git blob 121dfcb1d68b7234649d5c33ed6eb5234c37d917. Installed-SDK execution, full committed-head CI, real enrollment-to-entry-to-report acceptance and native Discord validation remain required. This candidate does not close private entry/provisioning, consent, erasure or release gates.
