# Composition, source reader and PostgreSQL acceptance candidate

This test-only batch combines the actual composition factory, core/controllers/browsers/runtime bridge, PostgreSQL store and Discord source-reader adapter. A local fictional fetchImpl returns bounded JSON Responses for the exact routes constructed by the adapter. No native fetch, real token, Discord client login, gateway or REST request is used. Listener attachment is exercised only on an in-memory EventEmitter.

The fixture requires GitHub Actions, a loopback formal_review_test database on port 5432 with the formal_review_admin login, disabled certification and empty production database/token environment values. It installs migration 012 only into an initially absent disposable fixture schema, creates a uniquely named restricted worker, seeds one fictional work binding, then drains and removes the fixture. It does not provision real work or apply a production migration/grant.

Assertions cover no automatic listener registration, privacy denial before selected-message retrieval, preview without writes, edited-source rejection, retry of the same confirmation after restoring exact preview text, one persisted report/receipt, source digest fidelity, receipt retry without another source fetch, learner/reviewer discovery and reads, explicit feedback confirmation, unchanged deadlines, revocation/expiry denial, shutdown and borrowed pool survival. SDK builders serialize captured payloads. Advancing the injected core/source clock does not advance the PostgreSQL clock.

Course/exercise/reviewer authority and verifyResources remain scripted test providers; real enrollment-reader composition and production preflight are not established here. Metadata discovery deliberately reuses the store worker pool in this fixture: it does not prove independent metadata-reader ACL isolation. The separate saved/owner PostgreSQL fixtures retain their dedicated metadata-reader permission tests. Typed preview/review fields and in-memory sessions do not establish durable approved consent or restart-safe recovery.

The new test runs sequentially after existing database fixtures on PostgreSQL 16/18 and requires zero skipped tests. No local execution or future-head CI pass is claimed by adding source. All runtime activation, source collection, private entry publication, channel permissions, production database work, erasure and deployment remain gated. This candidate is not native Discord or complete release acceptance.
