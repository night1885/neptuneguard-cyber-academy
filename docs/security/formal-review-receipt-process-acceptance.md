# Persisted receipt process-acceptance candidate

This test-only change adds a sequential step to the existing disposable PostgreSQL 16/18 matrix. It changes no runtime source, startup wiring, production schema, privilege, listener or Discord setting. Local checks validate JavaScript syntax only; PostgreSQL execution and subprocess acceptance are not claimed passed until the exact committed-head CI succeeds.

The parent requires GitHub Actions, disabled certification, empty production database/token environment values, and the loopback formal_review_test control database under formal_review_admin. It verifies database/login/server version, creates one unique recover_<UUID> database from template0, installs migration 012 there, and creates unique restricted worker and metadata-reader roles. Children independently reject nonfixture databases, logins, network targets, identifiers or environment. Cleanup closes fixture resources and drops only the unique fixture database and roles. No live service is a target.

The actual core/store submit and review operations execute in separate child processes. A test-only IPC marker is sent after the core returns its committed result; the parent kills that writer with SIGKILL before simulated user delivery. A fresh child initializes actual storage/core/recovery and inspects persisted receipts without any preview/session token. Repeated inspections must preserve one report, one review, two operation receipts and the original deadline. Reader ACL assertions reject body, feedback, digest and deletion access. Foreign actor/guild/work, scripted course denial and core-clock expiry remain unconfirmed without additional writes.

The IPC marker provides fixture ground truth; it is not native Discord receipt delivery or a test of every ambiguous network/commit boundary. Work provisioning, course/exercise/reviewer providers and selected source remain scripted fictional bindings. No real enrollment or practical grant is asserted. The expiry case advances the injected core clock, not the database clock. Recovery identifies the latest matching operation, not a specific lost confirmation attempt.

Passing this candidate establishes only the tested PostgreSQL/process-recreation behavior. Private recovery UI, real authority/resource verification, approved durable consent, exact-attempt recovery, cleanup and native Discord/release acceptance remain separate gates.
