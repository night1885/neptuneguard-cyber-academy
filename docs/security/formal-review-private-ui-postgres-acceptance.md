# Combined PostgreSQL-to-private-recovery-UI acceptance candidate

This test-only expansion opts the existing disposable composition fixture into recovery controls. It uses the actual composition, recovery service/wrappers, core, storage, saved-report/feedback handlers, real enrollment/course authorization and removal checks, plus fictional HTTP source responses. It adds no production runtime wiring, entry publication, grant, configuration, migration or deployment.

The existing loopback GitHub Actions fixture creates a unique database, installs fixture migrations and obtains the fictional learner's permanent student ID through the existing approval service. This expansion reuses that identity. Four unique restricted logins now separate review persistence, enrollment/course reads, report discovery and receipt metadata. The receipt reader receives only required work/operation columns, not bodies, feedback, digests or mutation privileges. ACL assertions test these limits. The supplied verifyResources and exercise/reviewer providers remain scripted, so this is not a production privilege or practical-authority audit.

The journey asserts unconfirmed empty inspection without source collection; recorded submission inspection; learner/reviewer receipt refresh followed by saved report and feedback; four in-place acknowledgements per navigation journey; synthetic receipt-delivery failure with exactly one recovery lookup; public-origin rejection and a foreign-actor denial; and unchanged report/review/operation counts and original deadlines. Selected-source retrieval remains at three calls from the original preview/confirmation journey. Receipt views contain no body, feedback or body digest.

Real fixture enrollment revocation, injected core-clock expiry and actual course-removal events deny both learner and reviewer recovery. After fully disposing/draining and recreating composition, old confirmation tokens remain unconfirmed, while persisted latest-operation receipts reopen through the new private UI. Borrowed receipt/storage pools remain open until fixture-owned teardown. Unrelated course access and the existing student ID remain unchanged.

Component recreation is not a process restart; the separate killed-writer/fresh-reader fixture covers its own narrower process boundary. Restoring the injected clock for a new composition is not durable clock recovery. Interaction methods and source HTTP responses remain fictional; installed SDK builders serialize payloads but do not prove live Discord acceptance. Latest-operation inspection is not exact-attempt recovery or durable consent.
