# Academy entry-point shutdown integration

This patch supersedes the not-installed status of application-shutdown-preparation.md and the entry-point limitation in database-runtime-integration.md. It wires index.js to createAcademyApplication while preserving the existing course handler body, academy database initialization SQL, credentials, and TLS settings. No certification migration or activation is added.

The application retains the certification runtime handle, tracks accepted academy interactions, database initialization, and Discord login, and installs SIGINT/SIGTERM handling before starting login after configuration and listener setup. Shutdown synchronously stops academy admission and calls certification detach to stop certification admission. Academy drains and certification closure are then awaited before closing the shared academy pool and destroying Discord. Repeated shutdown requests reuse one operation.

Login and uncaught startup/handler failures trigger sanitized cleanup and a nonzero exit. They do not await cleanup from inside the tracked task, avoiding a self-drain deadlock. The existing academy handler still handles ordinary interaction errors privately. Constructor/configuration failures before startup still throw before login; required environment validation remains unchanged.

Eight mocked integration tests cover delegation, startup failure, login failure, pending initialization, pending interactions, pending login during signals, and listener/resource ownership. The existing shutdown-controller deadline remains 15 seconds and its earlier timeout tests still apply. The tests do not import/run the live entry point, log into Discord, use production databases, or emit real process signals. The source-level entry-point assertion verifies wiring, not a live end-to-end run. This commit's CI has not yet run at preparation time.

Only promises returned/awaited by handlers are tracked. Future fire-and-forget jobs need explicit tracking. Forced exit cannot establish whether remote writes committed. Academy pool operations retain their existing settings; certification uses its separately bounded pool. Least-privilege roles, TLS review, real shutdown/restart testing, full learner/owner testing, and security review remain outstanding. No merge, publication, deployment, production migration execution, or enrollment activation occurs in this patch.
