# Bug Bounty

One course with named modules and readable lesson titles. Internal filenames are references, not separate courses.

## Delivery status

This branch contains work in progress for the full academy course. This first batch contains two authored lessons; it is not the complete course and does not add a student-facing entry. Academy registration, lesson delivery, integration tests and release remain pending.

## Practice model

Students practice through Bugcrowd and other bug-bounty programs only where they are eligible and the particular asset, account, method and intensity are permitted by current written terms. The platform is not blanket testing authorization. Private programs require applicable access or invitation. Local or offline examples may help explain a tool but are optional preparation, not the primary practice environment.

A technique that a selected program prohibits must not be performed there. Choose another explicitly authorized opportunity or complete the analysis without execution. Do not turn an advanced technique into a required live action on an unsuitable program.

## Teaching standard

Each lesson explains why and when to use a technique, prerequisites, exact commands or tool steps, consequential options, expected and alternative results, evidence limits, a bounded exercise, explained answers and cleanup. Expected behavior must remain distinct from observed results. Tool version checks and shell syntax checks do not establish practical reproduction.

## Preservation and release boundaries

Do not modify other courses, staging or the verification bot. Do not redesign enrollment, access, progress, reporting storage, grading or certification. No bounty, valid finding or payout is required to complete a learning activity. Learner acceptance is owner-managed, not a release gate. Repository writes, PR opening, merge and academy deployment require their separate approvals.
