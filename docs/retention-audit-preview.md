# Audit retention preview — read-only preparation

This separate owner-only, explicitly enabled library previews the certification audit-event category. It is not runtime-wired, scheduled, deployed, or deletion-capable. No live records are queried by adding these files. Its explicit asOfUtc cutoff must be canonical UTC with exactly six fractional digits; a JavaScript Date or millisecond-only string is rejected instead of silently losing precision.

The existing approved UTC three-calendar-month calculator computes the whole-millisecond portion of the deadline, including end-of-month clamping. The original sub-millisecond remainder is preserved separately and compared using BigInt microseconds. Eligibility begins at the exact boundary, not one microsecond earlier. It does not substitute 90 days or round a timestamp across a calendar-day/month boundary. Unsupported source/deadline ranges and nonpositive event IDs are flagged for review rather than guessed.

The reader selects only event_id as text and created_at formatted explicitly in UTC with six fractional digits. It does not read action, actor/subject Discord IDs, or details. Event IDs and keyset cursors stay exact decimal strings, including IDs above JavaScript's safe-integer range. Pages default to 100 and cap at 250. Each call uses a REPEATABLE READ READ ONLY transaction; several pages are not a single historical snapshot. The cutoff is applied to current snapshot records, not a reconstruction of prior database state.

Foreign keys referencing the audit table conservatively block timing candidates for separate review. No child data is read or cascaded. The catalog check is not exhaustive proof of indirect dependencies or preservation requirements. Reports state planningOnly=true, executionAuthorized=false, preservationReviewed=false, and providerCopiesVerified=false. A timing candidate is not a deletion authorization, reviewed preservation decision, or provider/backup erasure claim. Enrollment/access timing remains separate.

Tests cover exact microsecond boundaries, month-end/leap-year clamping, malformed or unsupported timestamps, large IDs, disabled/unauthorized/input rejection before connection, rollback cleanup, and a real column-only SELECT login in disposable loopback certification_test schemas. PostgreSQL integration checks non-UTC session formatting, pagination, hidden-column/delete rejection, unfamiliar foreign-key blocking, and unchanged audit rows. CI runs PostgreSQL 16 and 18; skipped tests do not establish acceptance. Test-only role/schema creation and cleanup are not production migrations or grants.

This batch adds no live query, production permission/configuration change, scheduler, notification, deletion, merge, or deployment. Actual execution, preservation review, dependency ordering, retries/failure handling, provider/backup handling, and release acceptance remain outstanding.
