# Shared-enrollment retention transaction - staged unit-tested backend

This default-disabled library has no runtime route, CLI, scheduler, environment activation flag or production credentials/grant bundle. It requires explicit owner, direct restricted executor identity, database/schema, an expected snapshot hash and a preservation-review provider. The application login is rejected. The preservation workflow and reviewer-authority decision remain unresolved; no fixture allow decision is a production default.

The transaction pins built-in resolution to pg_catalog, checks identity and limited privileges, locks the parent table and target parent row before the course table, validates actual foreign-key shapes and blocks unfamiliar dependencies, delete triggers or rewrite rules. It reads bounded current course metadata and blocks any linked lab. The existing snapshot helper must reproduce the caller's expected hash before and after review. A matching hash is evidence binding, not authorization by itself; fresh actor/subject/category/hash-bound preservation clearance is also mandatory.

Only reviewed completed course rows are deleted, followed by the guarded parent, with strict returned-key and row-count checks in the same transaction. Parent approval timestamps stay canonical six-digit UTC strings so the final predicate does not lose microseconds. Audit and lab rows are neither read for private contents nor deleted. The separate audit schedule remains independent. Missing parents are reported as not_found, not claimed previously deleted.

The locks are conservative and can block writes. Parent-first order matches the application services, but uncoordinated child writers may still cause timeout/deadlock rollback. Query-admission, statement, lock and idle limits are not a universal cancellation guarantee; provider abort is cooperative and pool acquisition bounds remain the caller's responsibility. A COMMIT acknowledgment failure can be ambiguous even after a rollback attempt, so no blind retry or no-deletion claim is supplied.

All 26 local tests use the actual committed snapshot helper, verified by its Git blob hash, and mocked database responses. They check admission, status variants, dependency/preservation rejection, ordering, counts, exact approval timestamp binding, failures and cleanup. SQL, real PostgreSQL permissions, concurrency and actual rollback have NOT been accepted by this batch. Dedicated disposable PostgreSQL 16/18 acceptance tests are the next required batch. The existing certification unit glob and early syntax checks discover these files.

No production invocation, live learner-record query/deletion, role creation, grants, provider action, merge or deployment is included. Scheduling/retries/alerts, durable preservation/evidence handling, final documents, provider-copy limits, target acceptance and release authorization remain separate gates.
